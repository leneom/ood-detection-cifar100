# Places365 amendment 1 — metadata location only, frozen before archive download

The original Places365 declaration listed `http://data.csail.mit.edu/places/places365/categories_places365.txt` as a direct category URL. A metadata-only HTTPS HEAD check after freezing the declaration returned 404 for that path; no Places365 archive was downloaded, no image was decoded, and no OOD score was seen. The official torchvision Places365 loader instead obtains `categories_places365.txt` by extracting the standard development-kit archive. [Its source code](https://docs.pytorch.org/vision/main/_modules/torchvision/datasets/places365.html) retains the same category-file MD5 `06c963b85866bd0649f97cb43dd16673` and development-kit archive MD5 `35a0585fee1fa656440f3ab298f8479c`.

Obtain the category file **only from the already specified and MD5-verified** `filelist_places365-standard.tar`; ignore the nonworking direct category URL. Verify the extracted category file MD5 independently and preserve its SHA-256. The image archive, validation annotation file, all 36,500 rows, model/checkpoint/score grid, preprocessing and scientific boundary of the original frozen protocol are unchanged. No alternative data source or subset is authorized by this amendment.
