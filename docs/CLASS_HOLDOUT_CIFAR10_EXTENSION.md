# Frozen 80-class holdout-model CIFAR-10 extension v0.1 — 2026-09-28

## Scope and scientific boundary

Apply the **three already selected and fully audited** 80-class CIFAR-100 held-out-fine-class ResNet-18 checkpoints (seeds 0/1/2) to the complete official CIFAR-10 test split as an additional natural OOD population. This is a post-hoc extension chosen after the same-source held-out-class results were viewed. CIFAR-10 has also appeared in earlier project work. It is therefore exploratory, not untouched external confirmation, a method-development validation set, or a claim that different OOD populations are directly comparable on AUPR.

The original CIFAR-100 class-holdout ID optimization/validation/test partitions, all three checkpoint selections, ID feature bank, three ID-only fitted temperatures and four ID-only acceptance thresholds remain frozen. Do not retrain, refit, recalibrate, choose a method on CIFAR-10, or change any previous completed result. Use only 8,000 official CIFAR-100 ID test rows as the reference and all 10,000 official CIFAR-10 test rows in their original order. No CIFAR-10 train image enters this extension.

## Fixed evaluation

- Load the locally verified official CIFAR-10 test data as `uint8` NHWC 32×32 RGB, original rows 0…9999, preserving its original labels solely for provenance. Apply the exact frozen CIFAR-100 ID normalization, no test augmentation, and record source archive/extracted-test hashes plus a pixel-array fingerprint. Do not select a subset or use OOD labels for scoring.
- Extract all 10,000 raw 80-dimensional logits and 512-dimensional penultimate features for each frozen model. Save original rows/labels and predictions. Compute the original fixed T=1 MSP, Energy, MaxLogit and Entropy, plus normalized KNN-50 and pooled 1%-shrinkage Mahalanobis scores using **only the 36,000 existing optimization-ID feature rows**. Independently check fit/probe agreement with the original class-holdout extraction. Use the same six methods under T=1 and each model's original ID-only fitted temperature; MaxLogit/KNN/Mahalanobis remain temperature invariant.
- For each seed/method/variant, compare the frozen 8,000 ID-test score vector with all 10,000 CIFAR-10 scores. Report AUROC, AUPR-out, AUPR-in, FPR95-ID (ID test empirical threshold), and actual CIFAR-10 acceptance at each original 80/90/95/99% ID-validation target. Report original ID-test acceptance at those thresholds. Treat higher score as more OOD, ties as half credit in AUROC, and ties as accepted at the threshold. Original ID-test scores and fixed thresholds are reused bit-for-bit.
- The comparison prevalence is 10,000/(8,000+10,000)=55.56%, unlike 2,000/(8,000+2,000)=20% in the held-out-class study. Do not compare AUPR values across these populations as if prevalence were equal. Display all six methods, both variants, three per-seed points with mean/sample SD, population counts, and a side-by-side AUROC/acceptance description of the two OOD populations without ranking/optimizing from test results. No cross-population macro or significance claim.

## Evidence and operational guard

Before first new inference, source-bind this protocol, existing baseline/class/paired-bootstrap completion gates, three checkpoint and score-audit hashes, the original ID score arrays/threshold records, and the verified CIFAR-10 test source. Independently audit the full 10,000-row population and hashes. Sequential GPU inference only after checking no project trainer/extractor is active and three two-second-spaced GPU samples each satisfy ≤4,096 MiB VRAM, ≤55% GPU utilization, ≤10% memory utilization and ≤55 W. If busy, defer without creating partial output. Save full raw arrays/source snapshots and refuse overwrite. Independent CPU audits must recompute source/row/pixel alignment, scores, fixed thresholds, AUROC/AP/FPR and all acceptance masks/counts before a report or completion gate is written. Preserve failed attempts separately; do not present a partial seed as a full extension.
